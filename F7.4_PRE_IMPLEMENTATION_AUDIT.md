# F7.4 PRE-IMPLEMENTATION AUDIT

## 1. Current Request & Response Flow
1. **Frontend**: Sends `POST /api/v1/ai/command` with payload `{"user_id": X, "command": "...", "days_back": 90}`.
2. **FastAPI Endpoint (`backend/main.py`)**: Validates against `CommandRequest`, routes to `AIInteractionLayer.process_command()`.
3. **`AIInteractionLayer`**: Detects intent, constructs a `parameters` dict (including intent, goal, date match, task types), and routes to `AIBrainController.process_intent(intent, parameters)`.
4. **`AIBrainController`**: 
   - Receives loosely typed `params` dict.
   - For `plan_day` intent, routes to `_execute_central_planning`.
   - Executes classical pipeline (`DecisionPipeline`), evaluates quantum suitability, executes `ExecutiveCognitiveBrain`.
   - Returns a `Dict[str, Any]` containing `tasks`, `schedule`, `predictions`, `quantum_suitability`, `executive_summary`, `brain_orchestration`, and `executive_trace`.
5. **FastAPI Endpoint**: Wraps the result into `CommandResponse(intent=intent, result=result)`.
6. **Frontend**: The `JamMessage.tsx` component parses `response.result` using a generic recursive `ResultRenderer`.

## 2. Existing Implicit Contracts
- `BrainRequest`: Currently implicitly defined as the `parameters` dictionary built in `AIInteractionLayer.parse_command()`.
- `BrainResponse`: Currently implicitly defined as the raw `Dict[str, Any]` returned from `AIBrainController.process_intent()`.
- **Frontend Expectation**: `CommandResponse` MUST have `intent: string` and `result: Record<string, unknown>`. The UI uses `result.schedule` internally if it needs to, but mostly the JAM assistant renders the raw result dict using `ResultRenderer`.

## 3. Current Observability State
- Uses `AIMonitor` for duration (`perf_counter()`), intent usage tracking (`_INTENT_USAGE`), and logging high-level metrics.
- No granular trace ID propagated through the stages.
- `AIBrainController` execution is timed as a whole, but individual engine timings within the brain execution are not aggregated into a pipeline trace.
- The `executive_trace` is passed out directly from `ExecutiveCognitiveBrain` but isn't part of a formal pipeline-level execution trace.

## 4. Proposed Changes for F7.4
- Create `BrainRequest` schema in `backend/app/schemas/orchestrator.py` or similar location (e.g. `backend/app/orchestrator/models.py`).
- Create `BrainResponse` schema to rigorously define the return type of `AIBrainController`.
- Create observability structures: `BrainExecutionTrace` and `StageTrace`.
- Add `request_id` or `trace_id` passing through the `AIBrainController` pipeline.
- Implement explicit enums for `QuantumStatus` (e.g., `UNSUPPORTED`, `CLASSICAL_FALLBACK`, `QUANTUM_EXECUTED`).
- Implement rigorous error handling capturing stage-specific status (`SUCCESS`, `SKIPPED`, `FAILED`).

## 5. Potential Breaking Changes
- If we change the keys inside the `result` dictionary in `CommandResponse`, the `ResultRenderer` will render them differently, but it won't crash since it's dynamic.
- Must ensure that if frontend is checking for `result.schedule` elsewhere, it is not broken. (Will verify frontend usage of schedule).

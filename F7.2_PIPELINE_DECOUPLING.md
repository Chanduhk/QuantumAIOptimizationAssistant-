# F7.2 Central Brain Pipeline Decoupling Implementation Report

## Objective
Remove the runtime dependency of `DecisionPipeline` and `AdaptiveScheduler` on the legacy god-object `AIOrchestrator`, completely shifting responsibility for dependency resolution to `EngineRegistry` and orchestrated by the `AIBrainController`.

## Execution Steps

### 1. EngineRegistry Expansion
- Analyzed `AIOrchestrator` to identify all engines that were being dynamically constructed and supplied to `DecisionPipeline`.
- Expanded `EngineRegistry` to include lazy-loading factory getters for:
  - `VectorMemorySystem`
  - `ContextEngine`
  - `RLScheduler`
  - `FeatureStore`
  - `AIMonitor`
  - `AIKnowledgeGraph`
  - `CognitiveEngine`

### 2. DecisionPipeline Refactoring
- Removed the `orchestrator` parameter from `DecisionPipeline.__init__`.
- Dropped the `AIOrchestrator` import.
- Modified `DecisionPipeline.initialize_pipeline()` to pull all dependencies (cognitive, context, scheduling, memory, feature extraction, graph, and monitor) exclusively from the injected `EngineRegistry`.

### 3. AdaptiveScheduler Verification
- Inspected `AdaptiveScheduler` and verified that it did not explicitly instantiate or require `AIOrchestrator`. It correctly inherited dependencies via properties on the `DecisionPipeline` instance provided by the `AIBrainController`. Since `DecisionPipeline` continues to expose those identical properties, no logical changes were needed in the adaptive scheduling layer.

### 4. Controller Verification
- Confirmed that `AIBrainController._get_decision_pipeline()` now properly constructs the `DecisionPipeline` utilizing only `session`, `days_back`, and `engine_registry`.

### 5. F7.2 Decoupling Unit Tests
Created a dedicated test suite (`backend/tests/test_f7_2_pipeline_decoupling.py`) that verified:
- Construction of `DecisionPipeline` without `AIOrchestrator` succeeds.
- Initialization (`initialize_pipeline`) is completely isolated and utilizes only `EngineRegistry`.
- `AIBrainController` correctly constructs and injects dependencies into `DecisionPipeline`.
- Cold-start and fractional scheduling fallbacks remain functional when bypassing `AIOrchestrator`.
- Top-level intent (`plan_day`) routing successfully executes the pipeline.
- Exceptions propagate reliably.
